1 · The brief, refined

One parcel, four sites, the same questions

The rough idea was “audit the booking flow and compare competitors”. To make that measurable, every site got the identical shipment, the same stop rule, and the same scoring rubric, and every number on this page comes from a script you can rerun.

Research questions

  • How many screens and fields stand between a visitor and a price?
  • Can a first-time customer book without an account?
  • Is the price honest: inclusions, add-ons, delivery date?
  • What changes on a phone?

Rules of the walk-through

  • Identical lane and parcel on every site
  • Dummy shipment data only; no personal data typed
  • No accounts created; stop at sign-in walls
  • Stop before any payment screen
  • Non-essential cookies rejected everywhere

9 · Method and limits

How to reproduce this

Process

  1. Walk each quote flow by hand on desktop, counting visible inputs per screen with a form-audit snippet.
  2. Repeat the first screens at 375 px: redirects, input text size, CTA position.
  3. Run Lighthouse mobile and desktop on each homepage and booking entry page.
  4. Log every issue with evidence, tag one or two heuristics, rate severity 1–4.
  5. Score fixes for impact and effort; turn the three biggest unknowns into A/B tests.

Limits

  • One evaluator, one lane, one session on . Sites change; rerun before quoting numbers.
  • Heuristic review finds likely problems. It does not replace testing with real customers.
  • Lighthouse lab scores vary run to run by a few points.
  • DHL’s failure may be lane-specific; it was retried twice.
